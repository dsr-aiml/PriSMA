# PriSMA 0.8.7

This release corrects the failures found in the saved Wikipedia, Amazon and Canva assessments and the attached X worker log. It also improves the landing scene, report history and Accounts page.

## Evidence and collection

1. Captured NUL characters are replaced with one Unicode replacement character in analysis text. The original source text is stored losslessly and decoded for evidence export and reassessment. Exact citation offsets refer to the normalized copy. A rejected source uses its own database savepoint. Its exclusion is recorded without discarding other valid sources. Source numbering stays safe when later evidence is appended after an exclusion.
2. Discovery checks target relevance before spending Fetch allowance. Same-organisation hosts and hosted articles do not automatically establish target capabilities. Background documents remain inspectable when they were already retained. They are excluded from target findings and new research answers, including report orientation from older assessments.
3. A Chromium launch and readable page coverage have separate statuses. Verification forms, short challenge pages, login and subscription gates are access observations. Earlier static failures stay in the audit trail when a later rendered page succeeds. Partial retained HTML is checked too.
4. The requested page and homepage identity lead the product description. A detailed feature page does not displace the primary product description.
5. Identity SDKs and tracking code have separate resource roles. Browser-delivered paths do not create original repository source groups. Repeated form API rows are consolidated while their claims remain available. Delivery origins and form boundaries use consistent identities.
6. The overview shows acquisition coverage. API rows expose declaration, client-reference, unsubmitted-form, request-attempt or observed-response basis. Request-attempt edges keep their attempt labels. Bare and www aliases can follow and expose published navigation while actual request and redirect URLs are preserved.
7. Focused and existing regression suites cover storage recovery, citation spans, source intake, repository scanning, reassessment, ownership and export preservation. No provider calls are needed for these tests.

## Workspace

8. The landing scene keeps pointer-following perspective, flowing paths and the three source/architecture/evidence layers. The panels have a shallower angle and clearer text. Small screens use stacked panels. The headline keeps a 68px maximum and scales down with the viewport. Reduced motion and off-screen animation pauses are preserved.
9. The desktop report list has a four-row viewport and hidden scrollbars. It loads history in pages, supports keyboard scrolling and retains the report picker. Refresh merges new reports without dropping an already loaded boundary row. Compact/mobile navigation continues to use the picker.
10. Accounts shows real daily assessment creation over 28 UTC days, saved assessment outcomes, retained source and question totals, and four recent assessments. Activity is scoped to the signed-in owner. Reference reports are excluded. Existing profile, password, session and clear-data controls are preserved.

## Validation and remaining checks

The backend and updater suites passed together. The frontend production build and TypeScript checks passed. Offline replay of the supplied normalized report snapshots confirmed that Wikipedia's Swagger articles were excluded, Amazon's challenge page produced no product API, Canva's main product identity led its summary, and fake https/web module groups were absent. Replay used saved exports rather than new website visits; compact exports do not contain every original raw HTML response.

The build environment has no Docker daemon or usable downloaded Chromium binary. Actual Docker browser startup and interactive UI checks remain manual. The Node build used a local-only resource-probe workaround because this execution environment does not expose /proc. That workaround is not part of the application or update.

Existing saved assessments are not silently replaced. Use Reassess for a new interpretation of retained sources. Use Refresh when new collection is wanted. The release does not change API keys, provider quotas, models, custom assets or Docker volume contents.

## Local preparation

The supplied source ZIPs omit the installed root release record. The scaffold therefore includes a read-only preparation step. It checks the installed 0.8.6 marker and project record, verifies the exact predecessor hashes of every affected file, and creates a normal version-2 overlay bound to the installed manifest checksum. The ordinary installer still validates that overlay and refuses local edits, missing files, unexpected additions and checksum mismatches.

Run preparation and the upgrade as your normal user. Only Docker commands use sudo. A dry run changes no project files or services. The installer stops the inference and browser profiles with --remove-orphans, keeps named volumes, and preserves .env. It never uses down -v.
