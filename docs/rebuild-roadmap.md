# PriSMA rebuild roadmap

## 0.5.0 — Evidence foundation

Implemented: bounded repository/document intake, inventory review and selection, format/classification metadata, preservation of paths/indentation, structural declaration extractors, full document URL seeds, relevant-passage prioritization and compact model responses. Product methodology is centralized; diagnostics remain specific to the run.

Acceptance: import the existing HTTP test-service report and a repository bundle; inspect classification, structural results and exact citations. Static extraction must work without model calls. Actual model latency/quality, browser behavior and live provider acceptance remain manual checks. This release does not complete the broader intelligence or visual redesign.

## 0.6.0 — Deeper architecture assessment

Implemented: resolvable JavaScript/TypeScript relative modules and nested Express mounts, Mongoose model fields/references, separate configuration contexts, manifest package boundaries and Compose build links, canonical technology rows with dependency groups, source inventory navigation and graph context filters. Source-unit selection replaces model-copied extraction quotes; exact excerpts and offsets remain server-owned. Ollama embedding passages are split without discarded characters, with byte-weighted normalized pooling and a distinct cache identity.

Public collection has per-run Search/Fetch budgets capped by administrator limits and optional bounded direct public file inspection, defaulting to eight requests. Raw HTML discovers linked specifications/scripts; targets and redirects are scoped and public addresses are pinned with TLS hostname verification. A public GitHub branch ZIP can enter the same intake review. Requests remain opt-in and provider counts remain separate from direct reads.

Implemented cooperative stop, checkpoint reports, resume over retained snapshots using compatible cached responses, owner-checked run comparison, specific empty-result diagnostics and export metadata. Reassessment does not expand the crawl; a new web assessment explicitly starts collection. Source documents never receive fixture facts or cached results from other accounts.

Remaining research: additional language/framework grammars, complex call/data flow, alias reconciliation, separately evaluated entailment checking, incremental crawl expansion, real-source held-out benchmarks and lightweight-model measurements on the user's device. No model substitution is justified without those measurements. Stop cannot terminate an already submitted upstream request; hard-crash recovery and operational hardening remain in the next release.

Acceptance: multiple independent public products and imported repositories produce traceable results against manually reviewed expected facts. Irrelevant/contradictory/partial sources remain inspectable. A sparse map must explain its actual evidence coverage. A rich map must have source-backed edges and details.

## 0.6.5 — Assessment workspace foundation

Implemented: dedicated results URLs and readable assessment dashboards, separate evidence-aware comparison, snapshot reassessment, additive source reviews and staged removal, individual GitHub/local acquisition records, larger selectable collection allowances, explicit hosting/capability/licence parsing, bounded simple Mermaid topology, canonical aliases and focused semantic relationship packets. Existing report contracts, account boundaries, typography, theme palettes and model budgets remain intact.

Acceptance: use the saved README/API exports first, then a separate public GitHub project and economical live URL assessment. Inspect exact citations, model additions, staged removal, old/new report isolation and both sides of a comparison. Runtime/provider/model acceptance is documented in delivery/release/verification.md.

## 0.6.6 — Syntax scanners and source lifecycle

Implemented: priority-based archive admission; larger bounded intake; native JS/TS and Python syntax records; resolved aliases/build outputs/imported calls; source module groups; declared types and supplied HAR records; public source-map expansion; honest scanner coverage; compact JSON and portable original evidence; worker-side repository refresh; focused snapshot reanalysis; account-scoped report deletion and lazy source content. The architecture and implementation views share the same evidence references.

## 0.7.0 — Research workspace

Implemented: dedicated Overview and evidence-derived Insights, grouped snapshot support, contextual inspectors, command navigation, custom accessible controls, virtualized inventories, API/schema/technology explorers, formal research summaries in exports, worker-based graph layout and optional on-demand spatial exploration. The constellation is exclusive to Architecture. Known ended queue deliveries can be reconciled conservatively; active/missing/unknown deliveries cannot.

Preserved: exact source/citation references, report ownership, separate reference history, snapshot reanalysis/origin refresh, original findings, model/provider budgets, light/dark foundations, Orbitron/Geist and custom theme controls.

Acceptance: compile/relevant checks and overlay safety are verified offline. Browser/GPU interaction, real source/model quality, deployment/HTTPS and backup restoration require runtime acceptance. See docs/research-workspace.md and delivery/release/verification.md. Wider framework grammars, benchmarked model changes and more complete flow analysis remain future parser work, not implied by visual depth.

## Assets

No new external asset is required for the evidence foundation. Optional user assets belong in frontend/public/: icon.png (transparent square brand mark, 256–512 pixels or larger) and fonts/SF-Mono-Regular.otf / SF-Mono-Medium.otf. Existing bundled fonts and coded SVG icons continue working. Any later asset request must specify its role, dimensions, format, local path and source; do not ask for generic decorative downloads.

## 0.6.7 — Report library corrections

Saved reports are deleted as complete records through the shared sidebar/library. Staged source removal remains available during intake. The separate source-deletion page has been removed. Assessment pickers are centered, and comparison selection and import separators have been refined.
